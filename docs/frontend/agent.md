# agent — 动态智能体

设置 → 显示 → 智能体用于配置首页全屏表情球。它与其他首页全屏模块互斥，优先级最低。

前端调用固定在 `de368ce3acdc5a70e871ee46ebbe8f60b11d3d6a` 的 MIT 许可 grok-ball 引擎，支持 `blob`、`wedge`、`gem` 三种形状、32 种内置表情和应用注册的 `listening` 表情。默认是米白色 `#f3f0ea`、待机表情 `02`；眼睛颜色按身体亮度自动取深色或浅色。

随机表情开启后每 8–15 秒切换一次。聆听状态始终优先；声音结束后恢复默认表情并重新开始随机计时。

智能体语音只在智能体首页可见时请求当前浏览器的麦克风。浏览器通过 AudioWorklet 将单声道音频重采样为 16 kHz PCM16，每 40 ms 发送到 `/ws/agent-voice`，以声音活动检测分句；约 320 ms 前置缓冲和 800 ms 静音结束判定会保留完整起始音节。最终 WAV 发送到 `/api/agent/transcribe`，再交给 Pi Agent。

待机状态先识别可配置唤醒词（默认“小薇小薇”），唤醒词后面的内容会直接成为第一轮问题。唤醒后保持最多 30 秒连续对话，空闲后回到等待唤醒词。开启“语音同步转文字”时，会每秒请求一次短窗口临时转写，并在停顿后替换为最终文本；只有最终文本提交给智能体。

智能体回复经 `/api/agent/chat` 以 NDJSON 流式返回，工具执行状态和文本增量实时显示。回复完成后经 `/api/agent/tts` 交给 ChatTTS，浏览器按顺序播放 WAV。播报期间暂停发送麦克风帧；停止按钮会取消 Pi 会话、丢弃待播音频并恢复聆听。录音和生成音频不落盘。

“开启输入框”默认开启，用于显示首页底部的文字输入、回复和对话控制区。关闭后隐藏整个底部面板，语音唤醒、识别和语音回复仍继续工作。

识别接口返回 `durationMs`，聊天流在首个文本增量和结束时返回 `metrics`（`firstTextMs`、`totalMs`），TTS 响应带 `x-vivoflow-tts-ms`，便于记录识别、首字和首段音频延迟。

设置中的“语音服务状态”按 Node、Ollama、Whisper、ChatTTS 四个 Tab 展示。Node 面板负责桥接服务检查和重启；Ollama 面板配置地址、刷新模型并测试连接；Whisper 面板分别检测 `base`、`small`、`medium`，未安装的模型在对应行显示独立下载按钮；ChatTTS 面板分别安装 Python 运行环境、准备官方模型并试听语音。下载任务显示实时进度并可单独取消。

`getUserMedia` 需要安全上下文。localhost 可以直接使用；生产后端默认通过 HTTPS 提供页面。局域网设备需要先安装并信任 VivoFlow 自动创建的根 CA，普通 HTTP 页面或尚未受信任的证书不满足麦克风访问条件。
